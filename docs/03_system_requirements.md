# 03. 要件（How much / 条件）

[READMEへ戻る](../README.md) · 前：[02. 要求](02_product_requirements.md) · 次：[04. UXフロー](04_ux_flow.md)

[02. 要求](02_product_requirements.md)を、テストで確かめられる条件にしたものです。IDは本体リポジトリの正式要求（v0.4）と同じで、全体では要求・要件98件、受入テスト22件あります。ここでは主なものを抜き出しています。

## 1. AIの回答

| ID | 要件 |
| --- | --- |
| AI-09 | AIの役割は、資料の検索と要約に限る。回答の内容は、引用できる区間の内容だけから作る。該当する区間がなければ答えない |
| AI-10 | 引用できる区間は「技術承認済み・使用停止でない・現行版・利用者が選んだ設備と一致・閲覧できる」をすべて満たすものに限る。この判定はプログラムで決定的に行う |
| AI-11 | AIは候補の区間を除くことはできるが、候補にない区間を加えることはできない。要約の後に、出典が引用できる区間に含まれるかを確かめ、違反があれば答えない |
| AI-12 | 要約では、数値・単位・否定・注意事項を出典の原文から引用する。資料にない手順・判断・操作の指示や、推測（「おそらく」「可能性があります」等）を加えない |
| AI-13 | 引用できる区間同士が食い違うときは結論を出さず、両方の出典を示して答えを控え、Q&Aに登録する |
| AI-14 | 緊急を示す質問（煙、発火、けが等）には、AIの生成を待たずに、事前に登録した固定の緊急案内を表示する |
| AI-15 | 作業と関係のない質問は「対象外」として答えを控え、Q&Aにも登録しない |
| AI-16 | 質問文に含まれる指示（「指示を無視して」等）で、規則を変えない |
| AI-04 | 「根拠あり」の回答には、利用者が選んだ設備を必須とする。選ばれていなければ「情報不足」として設備の選択を求める |
| AI-06 | 追加で求める情報は、質問の具体化と設備の選択に限る。物理的な操作を伴う確認は求めない |
| AI-07 | 正常・異常、運転を続けてよいか、設定の判断は、AIが行わない |

回答の4つの状態：

| 状態 | 表示 | Q&Aへの登録 |
| --- | --- | --- |
| 根拠あり | 要約、出典（教材名・版・開始〜終了時刻）、適用条件、該当区間の再生 | しない |
| 情報不足 | 足りない情報（設備、質問の具体化） | しない |
| 回答保留 | 理由と、Q&Aへ登録して担当へ依頼したこと | する（対象外を除く） |
| 緊急案内 | 固定の緊急案内と現場の連絡先 | しない |

## 2. 権限と本人確認

| 利用者 | 端末 | 認証 |
| --- | --- | --- |
| 作業員 | 共用端末 | 端末の認証と、名簿から名前を選ぶ（自己申告） |
| 管理者 | 共用端末または個別端末 | 端末の認証または個人アカウント。権限操作ごとに4桁のPIN |
| ベテラン（特定の人） | 個別端末 | 個人アカウント |
| 技術承認者 | 個別端末 | 個人アカウント。承認操作ごとに4桁のPIN |

| 操作 | 作業員 | 管理者 | ベテラン | 技術承認者 |
| --- | --- | --- | --- | --- |
| 教材の閲覧、要望、質問、コツの投稿、アップロード | ○ | ○ | ○ | ○ |
| 教材計画の追加・担当の指定・計画の変更 | — | ○（PIN） | — | — |
| 正式な教材の撮影・編集 | — | — | 担当分のみ | 担当分のみ |
| Q&Aへの回答 | 補足のみ | — | 担当範囲 | 担当範囲 |
| 技術承認（配信と再利用の承認、取り消し） | — | — | — | 担当範囲（PIN） |
| 使用停止・停止の解除 | — | ○（PIN） | — | 担当範囲（PIN） |

| ID | 要件 |
| --- | --- |
| AUTH-01 | 権限は画面だけでなくAPIで拒否する。AIの用途の判定で権限を変えない |
| AUTH-03 | 技術内容の承認は技術承認者だけが行う。管理者は技術承認をしない |
| AUTH-04 | 権限操作には本人の4桁PINを求める。PINの確認で、5分だけ有効な昇格トークンを発行する |
| AUTH-05 | PINは5回続けて間違えると15分ロックし、管理者が再設定できる。PINはハッシュで保存し、記録に出さない |
| AUTH-06 | 共用端末は管理者のPINで登録し、端末トークンで認証する。登録を取り消せば、すぐ使えなくなる |
| AUTH-07 | 名簿からの名前の選択は自己申告として記録し、権限の判定には使わない |
| AUTH-08 | すべての変更操作について、端末、認証された本人、自己申告の名前、日時、対象を監査記録に残す |

## 3. 承認と停止

| ID | 要件 |
| --- | --- |
| APR-01 | コツは技術承認者の承認後に配信する。承認前は投稿者本人と技術承認者だけが見られる |
| APR-02 | 教材・回答・コツの「配信」と「AIでの再利用」は、技術承認の後に有効になる。回答そのものは、承認を待たずに質問者へ届く |
| APR-03 | 技術承認者と管理者は、教材・回答・コツを使用停止できる。停止は次の検索・再生から即時に反映し、停止中は検索結果・再生URLの発行・AIの引用のすべてで拒否する |
| APR-04 | 承認・取り消し・停止・解除は、理由と本人を記録し、履歴を消さない |

```text
教材：計画中 → 制作中 → 技術確認待ち → 配信中 ⇄ 使用停止
                                  └→ 改版（新しい版が技術確認待ちへ。承認まで旧版が配信中）
コツ：投稿済み（未承認・本人と承認者だけが閲覧）→ 配信中 ⇄ 使用停止／非承認
回答：送信済み（質問者に届く）→ 再利用の承認 ⇄ 取り消し／使用停止
```

## 4. 録画・音声・メディア

| ID | 要件 |
| --- | --- |
| REC-01 | カメラの表示中は自動で録画し、「録画中」を常に表示する |
| REC-02 | AIタブでは直近30秒だけを保持し、古い部分は捨てる（2026年10月4日に変更） |
| REC-07 | 録画はアプリ内の領域にだけ保存し、写真ライブラリへ書き出さない |
| REC-05 | 音声入力は「録音中の分岐」と「保存済み区間からの認識」の2方式を切り替えられるようにし、技術検証で既定を決める（仮の既定は後者） |
| REC-06 | 通信できないときは送信待ちを表示し、届いていないのに「送信済み」と表示しない。再送は同じIDで、重複した投稿や通知を防ぐ |
| MED-02 | 話していない動作の区間も、ベテランが確認した区間メモで検索できるようにする |
| MED-06 | AIは現行版だけを引用する。旧版を引用した過去の記録には旧版であることを示す |
| CAM-06 | 機密の箇所は、区間の選択と切り取りで除く（ぼかしの加工は対象外） |

## 5. データと運用

| ID | 要件 |
| --- | --- |
| DATA-06 | サーバー一式（API、ジョブ、DB、動画の保存）はコンテナで構成し、工場内のPCで起動できる。同じ構成をクラウドでも起動できる |
| DATA-07 | 端末とサーバーの空き容量を監視し、少なくなったら管理者に警告する。容量不足で録画が黙って失敗しない |
| DATA-08 | 外部AIのAPIキーはサーバーの環境変数で渡し、Gitと端末に置かない。開発中は合成データ以外を外部AIへ送らない設定を、サーバーで強制する |
| DATA-03 | 削除したときは、派生データ（文字起こし、サムネイル、索引）にも反映する |
| NOT-02 | 回答の依頼は、個別端末を持つ担当のベテランへ、プッシュ通知と受信箱で届ける。共用端末には個人宛ての通知を送らない |
| NOT-08 | 担当のいない依頼は、管理者の受信箱に「未割当」として表示する |

## 6. 非機能

| ID | 要件 |
| --- | --- |
| NFR-01 | 主な操作は文字とアイコンで意味を示す。騒音の中で音声を使わなくても完結する。現場の手袋や端末で操作性を確かめる |
| NFR-02 | 質問を確定してから、回答の区間または保留を表示するまで10秒以内（p95）。動画のアップロードと解析は非同期にし、この時間に含めない |
| NFR-05 | 成功の指標を測るための計測イベント（質問の確定、回答の状態、区間の再生、依頼、回答、承認）を記録する |
| NFR-06 | AIの回答は評価セットで評価し、自動判定の全件合格と、人による判定で忠実性の違反0件を合格とする。AIの提供元・モデル・プロンプト・検索方式を変えたときは毎回評価し直す |

## 7. 受入テスト

| ID | 対応する要件 | 操作・条件 | 期待する結果 | 段階 |
| --- | --- | --- | --- | --- |
| AT-01 | AUTH-01、AUTH-03 | 作業員・管理者・PINなしで、制作や承認のAPIを呼ぶ | 拒否。管理者の技術承認も拒否 | 1 |
| AT-02 | 教材・制作 | 候補を登録し、ベテランが制作して承認後に公開 | 全員に計画が見え、未公開の素材は見えない。公開版だけを再生・引用できる | 1 |
| AT-07 | AI-09〜12 | 評価セットの「根拠あり」の質問 | 出典・適用条件・版を示し、期待した区間へ移動する | 1 |
| AT-08 | AI-04、06、07、10、13 | 評価セットの「保留・情報不足」の質問 | 原因や対応を推測せず、保留の理由を表示する | 1 |
| AT-11 | APR-02、03 | 承認・取り消し・使用停止 | 承認前・取り消し後・停止中は、検索・再生・引用のすべてで拒否 | 1 |
| AT-13 | REC-06、データ | 通信断、割り込み、容量不足、二重の再送 | 保存した範囲と未送信を表示し、二重に投稿しない。失敗を送信済みにしない | 2 |
| AT-16 | AUTH-04、05 | PINを5回誤る、期限切れの昇格トークン | ロックと拒否。監査記録が残る | 1 |
| AT-17 | NFR-06 | 評価セットの採点 | 自動判定30/30、人の判定で忠実性の違反0 | 1 |
| AT-18 | AUTH-06、07 | 登録を取り消した端末、名前を選んだだけの権限操作 | 拒否 | 1 |
| AT-19 | AI-14、15 | 緊急・対象外の質問 | 固定の緊急案内／対象外の表示。Q&Aに登録しない | 1 |
| AT-20 | DATA-06 | 工場内のPCに相当する環境で `docker compose up` | サーバー一式が起動し、ヘルスチェックが成功 | 1 |
| AT-22 | DATA-08 | 合成データ以外のメディアを外部AIへ送る設定 | サーバーが送信を拒否 | 1 |

ほかに、制作の要望の重複（AT-03）、録画と入力（AT-04）、用途の判定（AT-05）、コツの共有の確認（AT-06）、話していない動作の検索（AT-09）、通知（AT-10）、似た質問（AT-12）、別企業・停止・失効したURLでの取得（AT-14）、学習コース（AT-15）、容量の警告（AT-21）があります。各テストがどう実装されているかは[06. テスト](06_testing.md)にまとめています。
