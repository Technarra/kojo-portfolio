## 1. AIの役割を「資料の検索とまとめ」に限定する

| 項目 | 内容 |
| --- | --- |
| 背景 | 工場では、誤った手順や判断が事故や不良につながりかねない。外部レビューでも「回答してよい条件がデータとして定義されていないと、回答の可否が確率的な判断になり、テストできない」と指摘された |
| 検討した案 | A：AIが原因や対応を推測して答え、注意書きを添える ／ B：適用条件を構造化したキーで持ち、自動で照合する ／ C：AIの役割を検索とまとめに限り、引用できる区間だけから答える |
| 決定 | C。機械の操作などは資料を検索し、該当がなければAIは答えない。AIの判断で行動を促さない |
| 理由 | 安全を、確率ではなくコードの判定で守るため。テストで確かめられる形にするため |
| 捨てたもの | Aの推測による回答。Bの構造化した適用条件はPoCでは作らず、教材の設備・工程のタグで絞り、適用条件は画面に出して本人に確かめてもらう |
| トレードオフ | 答えられない質問が増え、ベテランへの依頼が増える可能性がある |
| 関連 | AI-09〜13、AT-07・08・17、評価セット |

## 2. 共用端末では、名前の選択と、重要な操作だけのPINに分ける

| 項目 | 内容 |
| --- | --- |
| 背景 | 作業員は会社支給の共用端末を複数人で使う。投稿した人は、アカウントではなく、その場で確認する形にしたい |
| 検討した案 | A：全員に個人アカウントでログインさせる ／ B：名前を選ぶだけで、すべての操作をできるようにする ／ C：端末を認証し、名前は選ぶだけ。重要な操作だけ本人のPINを求める |
| 決定 | C。承認・配信・停止・教材の追加など重要な操作だけ4桁のPINを求め、質問・閲覧・アップロードは名前の選択だけにする |
| 理由 | 普段の操作の手間を増やさずに、責任のある操作だけ本人を確かめるため |
| トレードオフ | 名前は自己申告なので、権限の判定には使えない。人の切り替え、失効、PINのロック、送信待ちの持ち主の管理が複雑になる |
| 関連 | AUTH-04〜08、AT-16、AT-18 |

## 3. 技術内容の承認は、技術承認者だけにする

| 項目 | 内容 |
| --- | --- |
| 背景 | 最初は、未承認のコツや危険な教材の扱いとして「技術承認者または管理者のどちらかの承認で配信する」と決めた。その後、管理者が単独で承認できることと、技術承認の要件が食い違うことに気づいた |
| 検討した案 | A：管理者も承認できる ／ B：技術承認者だけが承認する |
| 決定 | B（技術承認者は単独で承認できる）。使用停止は安全側の操作なので、管理者にも残す |
| 理由 | 技術的な正しさを確かめられる人に、承認の責任を集めるため |
| 捨てたもの | 最初の「どちらかの承認で配信」という決定。決定ログには元の決定を残したまま、変更を追記した |
| 関連 | AUTH-03、APR-01〜03、AT-01、AT-11 |

## 4. 工場のPCで動く構成にし、特定のクラウドに依存しない

| 項目 | 内容 |
| --- | --- |
| 背景 | 工場の映像や資料は、基本的に工場の中に置きたい。外部AIへ送らないデータの範囲は、PoCを通して決める |
| 検討した案 | A：クラウドのマネージドサービスを中心に組む ／ B：コンテナで構成し、工場内のPCでもクラウドでも同じ構成で動かす |
| 決定 | B。サーバーは工場内のPCに置き、クラウドを使う場合は東京リージョンにする |
| 理由 | データの置き場所を導入先に合わせて選べるようにするため |
| 設計への影響 | API・ワーカー・PostgreSQLをDocker Composeで起動する。ジョブの待ち行列と検索の索引もPostgreSQLに置き、部品を増やさない。メディアの保存先は差し替えられるようにする |
| トレードオフ | マネージドサービスの便利さを使えない。バックアップや監視を自分で用意する必要がある |
| 関連 | POC-01、DATA-06、AT-20 |

## 5. 開発中、外部AIには合成データだけを送る

| 項目 | 内容 |
| --- | --- |
| 背景 | 実データを外部AIへ送ってよい範囲が、まだ決まっていない |
| 決定 | 開発と評価は、機密を含まない卓上ボール盤の合成データで行う。合成データ以外を外部AIへ送る設定は、サーバーの許可リストで拒否する。送る側が付けたフラグは根拠にしない |
| 理由 | 実データを守りながら、AIの評価を先に進めるため |
| トレードオフ | 合成データで確かめられるのは、失敗の条件を再現するところまで。実際の質問・録音・教材での品質は、別に評価が必要 |
| 関連 | POC-03、DATA-08、AT-22 |

## 6. カメラは直近30秒だけを保持し、確認なしで添付する

| 項目 | 内容 |
| --- | --- |
| 背景 | AI画面の目的は「カメラを向けて、写っているものについてすぐ質問する」こと。当初の要求は「長く撮っても、古い区間を黙って上書きしない」だった |
| 検討した経緯 | 完成した画面を触って確認し、同じ日に2回作り方を変えた。1回目は撮影用のシートを別に開く形にし、2回目でそれをやめて、AIタブを開いた時点でカメラが起動する形にした |
| 決定 | AIタブを開くとすぐカメラが映り、端末のメモリに直近30秒だけを保持する。「質問する」で確認なしに添付し、ファイルや写真ライブラリには残さない |
| 捨てたもの | 撮影用のシート、録画全体を分けて保存し続ける方式、送信前の確認画面 |
| トレードオフ | 30秒より前の映像は残らない。区間の境界、音声、録画の確定の遅れを、OSごとに扱う必要がある |
| 確認の状況 | 「1分以上映した後に質問すると、添付が直近30秒（±1秒）になる」ことの実機での確認はこれから |
| 関連 | REC-01、REC-02、REC-07 |

## 7. プライバシーの要件は、実データを扱う前に判断し直す

| 項目 | 内容 |
| --- | --- |
| 背景 | 外部レビューで、自動録画に写り込む周りの人、質問動画の閲覧範囲、未送信の録画の消去時期が決まっていないと指摘された |
| 決定 | PoCの期間（合成データ、1つの工場）は一旦外し、実際の工場で実データを扱う前に判断し直す。データには閲覧範囲と保持期限の項目を先に持たせておく |
| 理由 | 合成データの段階では決めきれない運用の論点を、実データの前に必ず判断するため |
| トレードオフ | リスクとして記録し続け、Phase 4で確実に扱う必要がある |
| 関連 | POC-04、DATA-02、REC-01 |

## 8. 要求は削らず、実装の順番を4段階に分ける

| 項目 | 内容 |
| --- | --- |
| 背景 | 外部レビューで、2つのネイティブアプリ・バックエンド・AIの処理を同時に作るには、初期版の範囲が大きいと指摘された |
| 検討した案 | A：要求を削って初期版を小さくする ／ B：要求は残し、実装の順番を分ける |
| 決定 | B。Phase 1（一巡の骨格）→ Phase 2（現場の入力）→ Phase 3（制作と学習）→ Phase 4（実証の準備）の順に作り、それぞれ受入テストで完了を判断する |
| 理由 | 体験の全体像を保ったまま、早く一巡を確かめるため |
| 関連 | POC-06 |

## 9. 外部AIの比較をやめ、1つの提供元で評価する

| 項目 | 内容 |
| --- | --- |
| 背景 | 最初は、評価セットで2社以上の外部AIを比べて選ぶと決めた |
| 決定 | 開発中の外部AIはClaude Sonnet 5.5にし、比較は行わない。技術検証は、日本語の検索方式の決定と、評価セット30/30の確認に絞った |
| 捨てたもの | 複数社の比較 |
| 備え | AI接続部品をインターフェースで分け、提供元を差し替えられるようにした。提供元・モデル・プロンプトを変えたときは、評価セットで毎回やり直す |
| 関連 | NFR-06、AT-17 |

## 10. mainへの反映はPRだけにし、マージは自分が行う

| 項目 | 内容 |
| --- | --- |
| 背景 | 非公開リポジトリの無料プランでは、ブランチの保護を設定できなかった（APIが403を返した） |
| 決定 | mainへ直接pushせず、すべての変更をPRにして、マージは自分が行う運用にした。設計・タスク票・レビューはClaude Code、実装とテストはCodexに分担し、Codexはpushやマージをしない |
| 理由 | 実装をAIエージェントに任せても、何をmainに入れるかは自分で判断するため |
| 関連 | 有料プランに移ったときに、ブランチの保護を設定し直す |

## あえてやらなかったこと

| やらなかったこと | 理由 |
| --- | --- |
| AIによる正常・異常の判定、運転を続けてよいかの判断 | 誤った判断が事故につながりかねないため。資料に記載があっても、出典の内容として示すだけにする |
| 機械の自動診断や操作の案内 | 同上。物理的な操作を伴う確認もAIからは求めない |
| リアルタイムの字幕、映像の常時解析 | 基本の体験に必須ではないため。送信の時点で音声を確定して文字にする |
| 映像のぼかし加工 | 機密の箇所は、区間の選択と切り取りで除けるため |
