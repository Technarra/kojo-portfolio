# 01. ユーザー課題

[READMEへ戻る](../README.md) · 次：[02. 要求](02_product_requirements.md)

## きっかけ

技能継承に悩む父の課題がきっかけです。作業の手順や、異常に気づいたときの判断を、若い世代へ残す手段が必要だと考えました。

教育動画を作るだけでは足りません。目的は動画を量産することではなく、工場での作業効率を上げ、技術を継承することです。そのため、次の2つを中心の価値に置きました。

- **必要な場面に、早くたどり着けること**
- **現場の質問と回答が、次の学習に再利用されること**

## 利用者ごとの課題

| 利用者 | 困っていること | 必要としていること |
| --- | --- | --- |
| ベテラン | 同じ説明を何度も繰り返す。教材を作る時間がない | 短い手間で教材を作る。質問の状況をすぐ把握し、動画で答える |
| 学ぶ作業員 | 作業中に分からないことがあっても、すぐ確かめられない。教材の中から、目の前の設備に合う場面を探せない | 担当業務に必要な順序で学ぶ。作業中は対象を映して質問し、今必要な区間だけを見る |
| 管理者 | 何から教材にすべきか、誰が作るかを決めにくい | 教材の候補・制作計画・担当を管理し、作業員の「見たい」を優先順位の判断に使う |
| 技術承認者 | 現場に広がる情報が正しいかを確かめにくい | 教材・回答・コツを、配信する前に確認して承認する。危険が分かったらすぐ止める |

## 使われる場面の条件

画面や操作を考える前提として、現場の条件を次のように置きました。

| 条件 | 設計への影響 |
| --- | --- |
| 会社支給の共用端末を、複数人で使う | 個人のログインを毎回求めず、名前の選択と、重要な操作だけの本人確認に分ける |
| 手袋をしたまま、立ったまま、片手で操作することが多い | ボタンを大きくし、タップの領域を広げる |
| 騒音があり、音声入力が使えないことがある | 音声を使わなくても、文字だけで質問を完結できるようにする |
| 危険な状況（煙、けが等）が起きうる | 緊急時はAIの回答を待たせず、決まった案内と連絡先を出す |
| 工場の映像や資料には機密が含まれる | データを工場の中で扱える構成にし、開発中は外部AIに合成データしか送らない |

## 課題の整理

1. **必要な場面にたどり着けない**：教材があっても、設備・工程に合う区間を探すのに時間がかかる。
2. **その場で聞けない・伝えにくい**：作業中に分からないことがあっても、適切な人にすぐ聞けない。状況を文章だけで説明するのも難しい。
3. **AIが根拠なく答えると危険**：誤った手順や、正常・異常の判断を示すと、事故や不良につながりかねない。
4. **回答が残らない**：ベテランの回答が個別の対応で終わり、同じ質問への説明が繰り返される。

## 目指す状態

企画の段階で、初期版の合格像を次のように決めました。

> 管理者が計画した教材をベテランが公開し、若手が学び、現場で質問する。根拠がなければ回答を控えて担当者に届き、回答動画が承認後に次の質問で正しい区間として使われる。

## 成功の測り方（予定）

成果と安全の両方を見ます。工場での実証（Phase 4）で測る予定です。

| 観点 | 測るもの |
| --- | --- |
| 必要な知識への到達 | 質問を確定してから、該当箇所または回答保留が出るまでの時間。目的の箇所を見つけられた割合 |
| 教育・制作の負担 | 教材1本を公開するまでの、ベテランの実作業時間。同じ質問への回答回数 |
| 回答待ちの運用 | 依頼から担当の受諾・回答までの時間。担当のいない依頼や、長く待っている依頼の件数 |
| 学習と実務 | コースの進み方、現場の指導者による実技の確認、該当工程の手戻り。動画を見ただけで習得とは判定しない |
| AIの信頼性 | 根拠のない回答、別の設備の誤った引用、答えられるのに保留した割合、未承認の内容の共有 |
